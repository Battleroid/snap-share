Toasts are short, temporary messages about something that just happened, stacked in the bottom-right corner.

- Script: `pbToast({title, body, bodyHTML, status, variant, action, actions, timeout, ink, container, max})` returns the toast. `body` is text and is escaped; `bodyHTML` is markup you trust (`<code>` for a path); a DOM Node passed as `body` is appended. The toast's own markup carries no inline style, so it works under `style-src 'self'`; `toast.update({...})` changes it (loading to done), `toast.close()` removes it. `status`: `info` (default), `ok`, `warn`, `down`, `busy` (spinner, no timer); or `variant`: `success`, `warning`, `error`, `info`.
- `action: {label, onClick}` adds one button (`actions` takes up to two; the first is a secondary button, the second ghost). `onClick(toast)` runs, then the toast closes unless the action has `close: false`. Undo is the main use: perform the action at once, offer Undo in the toast.
- Timing: 5 s; errors (`down` / `error`) and `busy` stay until dismissed or updated; `timeout` sets your own (`0` keeps it). The timer bar pauses while the pointer or focus is on the toast. Escape or the X dismisses, and focus moves to the next toast or the page instead of being lost.
- Queue: at most three show (`max` changes it); later toasts wait, hidden, and show in order as others close. **Changed:** extra toasts used to push the oldest out. A queued toast's `update()` and `close()` work.
- Announcements: `pbInit` puts the stack (`div.pb-toasts[role=region]`, labelled `pbStrings.notifications`) and two hidden live regions in the page up front; each toast, and each status change through `update()`, is spoken through `pbAnnounce` (assertively for errors). **Changed:** the stack and the toasts are no longer live regions themselves: the region used to arrive with the first toast already inside it, so that toast went unannounced. `pb-toasts--top` puts the stack top-right.
- `pb-toast--ink` is a dark toast for neutral confirmations (copied, moved).
- Use toasts for results of the user's own actions. Use Notice for problems that need attention on the page, and Notifications for things that happened while they were away. Never put the only copy of an error in a toast.
