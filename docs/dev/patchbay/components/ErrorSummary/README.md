The error summary lists every problem in a form at the top, linked to the fields.

- Markup: `form[data-validate]` with fields in the field pattern (`div.pb-field` > `label.pb-field__label[for]` + control, see TextInput), each control with an `id` and `data-error="message"`. The summary is optional: a hidden `div.pb-errsum[role=alert][tabindex=-1]` with `pb-errsum__title` and an empty `ul` at the top of the form.
- `pbValidate(form)` checks native constraints on submit. For each invalid control it sets `aria-invalid="true"`, `data-invalid` on its `.pb-field`, and a `.pb-field__error` with the message (escaped) that joins the control's `aria-describedby`. It fills the summary with links to the fields (a link focuses its field), shows it, and moves focus to the first invalid field (`data-validate="summary"` focuses the summary instead). Fixing a field clears its error.
- **Changed:** it no longer stops other submit listeners. It prevents the native submit and fires a bubbling, cancelable `pb:invalid` on the form (`detail: {fields, submitter}`) first; cancel it to show errors your own way. Your own submit handler still runs, so check `e.pbInvalid` (the invalid controls, `[]` when the form is valid) before you send: `form.addEventListener('submit', (e) => { e.preventDefault(); if (e.pbInvalid.length) return; send(); })`. A form section (`data-section`) stays dirty, not busy, after an invalid submit.
- Messages say how to fix it: "Enter an email address like alex@lab.home", not "Invalid email". The same text appears in the summary and under the field.
- Use it for forms with more than two fields. Short forms only need inline errors.
